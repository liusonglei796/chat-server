# 01. 项目初始化与目录结构

> 本教程将指导你从零开始初始化 KamaChat 项目，并建立规范的目录结构。

---

## 📌 学习目标

- 了解 Go 项目的标准目录布局
- 掌握 Go Modules 初始化
- 理解各目录的职责划分

---

## 1. 创建项目

### 1.1 初始化 Go Module

```bash
# 创建项目目录
mkdir KamaChat && cd KamaChat

# 初始化 Go Module
go mod init kama_chat_server
```

`go mod init` 会创建 `go.mod` 文件，这是 Go 项目的依赖管理核心。

### 1.2 go.mod 文件说明

```go
module kama_chat_server

go 1.20
```

- `module kama_chat_server`：定义模块名称，后续导入包时使用
- `go 1.20`：指定 Go 语言版本

## 3. 核心概念解释

### 3.1 internal 目录

`internal` 是 Go 语言的特殊目录：
- 该目录下的代码**只能被同一模块内的代码导入**
- 外部项目无法导入 `internal` 中的包
- 用于存放内部实现，隐藏实现细节

```go
// ✅ 可以在 cmd/kama_chat_server/main.go 中导入
import "kama_chat_server/internal/config"

// ❌ 外部项目无法导入
// import "kama_chat_server/internal/config"  // 编译错误
```

### 3.2 pkg 目录

`pkg` 目录用于存放可被外部项目使用的公共代码：
- 工具函数（`util/`）
- 通用常量（`constants/`）
- 加密工具（`aes/`）
- JWT 工具（`util/jwt/`）
- 雪花算法（`util/snowflake/`）

### 3.3 分层架构

KamaChat 采用经典的分层架构模式：

| 层级 | 目录 | 职责 | 示例 |
|-----|------|------|-----|
| **Handler 层** | `internal/handler` | 处理 HTTP 请求/响应 | 解析参数、调用 Service、返回 JSON |
| **Service 层** | `internal/service` | 业务逻辑处理 | 用户注册逻辑、消息处理、权限校验 |
| **Repository 层** | `internal/dao/mysql` | 数据访问抽象 | 定义接口、隐藏 ORM 细节 |
| **DAO 层** | `internal/dao/mysql` | 数据库操作 | GORM、Redis 操作 |
| **Infrastructure 层** | `internal/infrastructure` | 基础设施 | 日志、中间件、短信 |

**调用链**：Handler → Service → Repository → DAO → Database

**依赖注入（DI）**：
Service 层通过构造函数注入 Repository 接口依赖，而不是直接访问全局变量：

```go
// internal/service/interfaces.go - NewServices 作为依赖注入入口（示意）
func NewServices(repos *mysql.Repositories, cacheService myredis.AsyncCacheService) *Services {
    sessionSvc := session.NewSessionService(repos, cacheService)
    userSvc := user.NewUserService(repos, cacheService)
    // ...

    return &Services{
        User:    userSvc,
        Session: sessionSvc,
        // ...
    }
}
```

**设计优势**：
- **单一职责**：每层只负责自己的事情
- **依赖倒置**：Service 层依赖 Repository 接口，而不是具体实现
- **易于测试**：可以 Mock Repository 接口进行单元测试
- **易于替换**：替换数据库只需修改 Repository 实现

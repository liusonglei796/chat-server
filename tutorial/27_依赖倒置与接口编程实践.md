# 依赖倒置与接口编程实践

在 KamaChat 的 `server.go` 中，有一个展示**依赖倒置原则 (Dependency Inversion Principle)** 的经典设计。

```go
type ChatServer struct {
    // ...
    // Broker 消息消费者（基于 Kafka）
    Broker *MsgConsumer
}
```

> **注意**：本项目当前只支持 Kafka 模式。

## 设计说明

当前项目只使用 Kafka 模式，因此直接使用 `*MsgConsumer` 结构体：

```go
// ✅ 直接使用具体实现
type ChatServer struct {
    Broker *MsgConsumer   // Kafka 消息消费者
}

// 初始化
cs.Broker = NewMsgConsumer(kafkaClient, messageRepo, ...)
```

## 工程理由：解耦 (Decoupling)

在分层架构中，**上层模块不应该依赖下层模块的实现细节**。

- `ChatServer` 属于 **Service 层**（业务逻辑）。
- `MsgConsumer` 属于 **基础设施层**（负责消息消费）。

`ChatServer` 聚合了消息消费者，通过依赖注入将具体的 Repository、CacheService 传入，使得业务逻辑与基础设施解耦。

## 测试理由：可测试性 (Testability)

使用结构体注入，也能实现良好的可测试性。你可以轻松造一个**假的 (Mock)**：

```go
// 假的 MsgConsumer，专门做测试用
type MockMsgConsumer struct{}

func (m *MockMsgConsumer) Publish(ctx context.Context, msg []byte) error {
    fmt.Println("假装发送成功了")
    return nil
}

func TestChatServer(t *testing.T) {
    server := ChatServer{
        Broker: &MockMsgConsumer{}, // 注入假对象
    }
    server.Run() // 跑得飞快，不需要任何真实环境
}
```

## 总结

在 Go 语言开发中，遵循以下原则能让你的代码更健壮：

1.  **依赖注入**：不要在结构体内部 `New` 用于依赖的对象，而是通过参数传进来（Inject）。
2.  **关注能力**：关注"它能做什么"（方法），而不是"它是谁"（结构体）。
3.  **解耦分层**：业务逻辑层与基础设施层分离，便于维护和测试。

# 17. 单聊与群聊消息处理

> 本章以当前代码为准，讲清楚消息从 WebSocket 进入后，如何在 Kafka Broker（MsgConsumer）内完成：解析 → 入库 → 单聊/群聊转发 → 异步更新缓存。

## 2. 消息业务流程（高层）

```mermaid
sequenceDiagram
    participant Sender as 发送者(WS)
    participant Kafka as Kafka Producer
    participant Consumer as MsgConsumer
    participant Repo as MessageRepo(MySQL)
    participant SessionRepo as SessionRepo(MySQL)
    participant Cache as AsyncCacheService(Redis)
    participant Receiver as 接收者(WS)

    Sender->>Kafka: Publish(JSON)
    Kafka->>Consumer: 从 Kafka 消费消息
    Consumer->>Consumer: Unmarshal ChatMessageRequest
    Consumer->>Repo: Create(Message)
    Consumer->>SessionRepo: UpdateLastMessage

    alt 单聊 ReceiveId=U...
        Consumer->>Receiver: SendBack 推送(若在线)
        Consumer->>Sender: SendBack 回显(若在线)
        Consumer->>Cache: SubmitTask 更新 message_list
    else 群聊 ReceiveId=G...
        Consumer->>Consumer: GroupMemberRepo.FindByGroupUuid
        Consumer->>Receiver: 遍历成员在线推送
        Consumer->>Sender: 回显
        Consumer->>Cache: SubmitTask 更新 group_messagelist
    end
```

## 4. 文本消息：handleTextMessage

Kafka 模式实现：

```go
// internal/service/chat/kafka_broker.go

func (mc *MsgConsumer) handleTextMessage(req request.ChatMessageRequest) {
    message := model.Message{
        Uuid:       snowflake.GenerateID(),
        SessionId:  req.SessionId,
        Type:       req.Type,
        Content:    req.Content,
        Url:        "",
        SendId:     req.SendId,
        SendName:   req.SendName,
        SendAvatar: req.SendAvatar,
        ReceiveId:  req.ReceiveId,
        FileSize:   "0B",
        FileType:   "",
        FileName:   "",
        Status:     message_status.Unsent,
        AVdata:     "",
    }

    // 规范化头像路径
    message.SendAvatar = normalizePath(message.SendAvatar)

    // 通过 Repository 入库（依赖倒置）
    if mc.messageRepo != nil {
        _ = mc.messageRepo.Create(&message)
    }

    // 更新会话最后消息
    if mc.sessionRepo != nil {
        _ = mc.sessionRepo.UpdateLastMessage(req.SessionId, req.Content, req.Type)
    }

    // 根据 ReceiveId 前缀路由
    if message.ReceiveId[0] == 'U' {
        mc.sendToUser(message, req.SendAvatar)
    } else if message.ReceiveId[0] == 'G' {
        mc.sendToGroup(message, req.SendAvatar)
    }
}
```

**要点：**

- UUID 使用雪花算法生成
- 入库使用 `MessageRepository.Create()`，不在 Broker 内直接调用 Gorm
- 更新会话最后消息和时间

## 5. 单聊转发：sendToUser（推送 + 回显 + 缓存）

```go
// internal/service/chat/kafka_broker.go

func (mc *MsgConsumer) sendToUser(message model.Message, originalAvatar string) {
    rsp := respond.GetMessageListRespond{
        Uuid:       message.Uuid,
        SendId:     message.SendId,
        SendName:   message.SendName,
        SendAvatar: originalAvatar,
        ReceiveId:  message.ReceiveId,
        Type:       message.Type,
        Content:    message.Content,
        Url:        message.Url,
        FileSize:   message.FileSize,
        FileName:   message.FileName,
        FileType:   message.FileType,
        CreatedAt:  message.CreatedAt.Format("2006-01-02 15:04:05"),
    }

    jsonMessage, _ := json.Marshal(rsp)
    back := &MessageBack{Message: jsonMessage, Uuid: message.Uuid}

    // 1) 推给接收者（若在线）
    if v, ok := mc.Clients.Load(message.ReceiveId); ok {
        v.(*UserConn).SendBack <- back
    }
    // 2) 回显给发送者（若在线）
    if v, ok := mc.Clients.Load(message.SendId); ok {
        v.(*UserConn).SendBack <- back
    }

    // 3) 异步更新缓存
    if mc.cacheService != nil {
        mc.cacheService.SubmitTask(func() {
            userOne := message.SendId
            userTwo := message.ReceiveId
            if userOne > userTwo {
                userOne, userTwo = userTwo, userOne
            }
            key := "message:list:" + userOne + "_" + userTwo
            // GetOrError -> append -> Set
        })
    }
}
```

**为什么要"回显"：**

- 发送者可能多端在线（手机/电脑），回显能保证自己所有端消息列表同步

**缓存 Key（以代码为准）：**

- 单聊：`message:list:<userOne>_<userTwo>`（先按字符串大小排序，保证同一对用户只有一个 key）

## 6. 群聊广播：sendToGroup（成员查询 + 广播 + 缓存）

群聊与单聊的关键差异：

1. 需要先查询成员列表
2. 对每个成员判断是否在线，在线才推送

```go
// internal/service/chat/kafka_broker.go

func (mc *MsgConsumer) sendToGroup(message model.Message, originalAvatar string) {
    rsp := respond.GetGroupMessageListRespond{
        Uuid:       message.Uuid,
        SendId:     message.SendId,
        SendName:   message.SendName,
        SendAvatar: originalAvatar,
        ReceiveId:  message.ReceiveId,
        Type:       message.Type,
        Content:    message.Content,
        Url:        message.Url,
        FileSize:   message.FileSize,
        FileName:   message.FileName,
        FileType:   message.FileType,
        CreatedAt:  message.CreatedAt.Format("2006-01-02 15:04:05"),
    }
    jsonMessage, _ := json.Marshal(rsp)
    back := &MessageBack{Message: jsonMessage, Uuid: message.Uuid}

    // 通过 Repository 查询群成员
    var members []model.GroupMember
    if mc.groupMemberRepo != nil {
        members, _ = mc.groupMemberRepo.FindByGroupUuid(message.ReceiveId)
    }

    // 在线推送
    for _, gm := range members {
        if gm.UserUuid != message.SendId {
            // 推送给其他成员
            if v, ok := mc.Clients.Load(gm.UserUuid); ok {
                v.(*UserConn).SendBack <- back
            }
        } else {
            // 回显给自己
            if v, ok := mc.Clients.Load(message.SendId); ok {
                v.(*UserConn).SendBack <- back
            }
        }
    }

    // 异步更新群聊缓存
    if mc.cacheService != nil {
        mc.cacheService.SubmitTask(func() {
            key := "message:group_list:" + message.ReceiveId
            // GetOrError -> append -> Set
        })
    }
}
```

**缓存 Key（以代码为准）：**

- 群聊：`message:group_list:<groupUuid>`

## 7. 文件消息与音视频信令

### 7.1 文件/语音消息：handleFileMessage

与文本消息主要差异：

- `Content` 为空
- `Url/FileSize/FileType/FileName` 会被写入

### 7.2 音视频信令：handleAVMessage

以当前实现为准：

- `av_data` 会被反序列化为 `AVData`
- 只有当 `MessageId == "PROXY"` 且 `Type` 属于 `start_call/receive_call/reject_call` 时才会入库
- 信令一般只转发给接收者，不回显给发送者（避免前端重复触发）

## 8. 消息权限校验

在 Kafka 模式下，发送消息前会进行权限校验：

```go
// 检查用户是否被禁用
if mc.userRepo != nil {
    user, err := mc.userRepo.FindByUuid(req.SendId)
    if err != nil || user.Status == 1 { // 1 表示禁用
        return
    }
}

// 单聊需要是好友关系
if req.ReceiveId[0] == 'U' && mc.friendshipRepo != nil {
    isFriend, _ := mc.friendshipRepo.IsFriend(req.SendId, req.ReceiveId)
    if !isFriend {
        return // 非好友不能发送消息
    }
}
```

## ✅ 本章小结

- 消息处理发生在 Kafka Broker（MsgConsumer）内：解析 → 入库 → 路由推送 → 异步缓存更新
- 单聊：推送给接收者 + 回显给发送者；缓存 key 会对两端用户 id 排序
- 群聊：通过 `GroupMemberRepository` 查询成员，在线广播；缓存 key 为 `message:group_list:<groupUuid>`
- 发送前会校验用户状态和好友关系
